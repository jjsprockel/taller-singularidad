# Taller 7 Ética gobernanza de datos y reproducibilidad

## Justificación

Integrar la protección de participantes, la gobernanza de datos y la rendición de cuentas sobre la IA en el protocolo.

## Resultados de aprendizaje

- Clasificar datos por sensibilidad y autorización de uso.
- Diseñar un plan de gestión, seguridad y minimización de datos.
- Analizar riesgos éticos de la IA y definir controles.
- Establecer trazabilidad, control de versiones y reproducibilidad.

## Contexto teórico

- Privacidad, confidencialidad, anonimización, seudonimización y riesgo de reidentificación.
- Principios de la OMS para IA en salud y responsabilidad humana.
- Consentimiento, uso secundario, propiedad, acceso, retención y destrucción.
- Proveniencia de datos, bitácora de IA, control de versiones, semillas y dependencias.

## Preparación

- Revisar requisitos del comité de ética aplicable.
- Inventariar datos y archivos previstos.
- Identificar plataformas que recibirían información.

## Actividad paso a paso

1. Clasificar cada fuente en verde, ámbar o roja según sensibilidad y autorización.
2. Trazar el flujo de datos desde origen hasta archivo final y publicación.
3. Aplicar minimización y definir responsables, permisos, respaldo, retención y eliminación.
4. Construir una matriz de riesgos con probabilidad, impacto, control y riesgo residual.
5. Redactar la declaración de uso de IA, supervisión humana e incidentes.
6. Crear una estructura de carpetas, nombres, versiones y bitácoras reproducible.

## Aplicación al proyecto

El estudiante debe aplicar la actividad al proyecto asignado y señalar con precisión qué parte elaboró de forma individual. Si el proyecto aún no dispone de datos o autorización, utilizará datos sintéticos, públicos o un caso de práctica. La entrega debe incluir la versión anterior, la nueva versión y una nota breve sobre las decisiones tomadas con apoyo de IA.

## Entregables

- Plan de gestión de datos
- Diagrama de flujo de datos
- Matriz de riesgos
- Plan de reproducibilidad
- Declaración de uso responsable de IA

## Lista de chequeo y KPI

- [ ] No hay transferencias de datos sin base de autorización.
- [ ] Cada archivo tiene propietario y regla de acceso.
- [ ] Los riesgos altos tienen control y responsable.
- [ ] El análisis puede reconstruirse desde datos autorizados y registros.
- [ ] El protocolo distingue anonimización de seudonimización.

**Criterio de avance:** completar al menos 80 por ciento de la lista, sin incumplimientos de privacidad, referencias inventadas o pérdida de trazabilidad.

## Retroalimentación semanal

Mesa de riesgos. El grupo intenta encontrar rutas de exposición, dependencia o reidentificación que el autor no haya previsto.
